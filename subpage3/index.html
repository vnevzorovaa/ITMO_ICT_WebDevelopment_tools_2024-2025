Сервис парсинга мероприятий

Сервис позволяет пользователю отправить список URL-адресов и получить структурированные данные: название события, краткое описание и статус выполнения запроса.

Предусмотрено два режима работы:

  • Синхронный — обработка выполняется сразу в рамках HTTP-запроса.
  • Асинхронный — задачи ставятся в очередь и обрабатываются рабочими процессами. Результат доступен по task_id.

Архитектура

  • API (FastAPI) — основной интерфейс для взаимодействия с клиентами. Поддерживает эндпоинты /parse/http, /parse/async, /tasks/{id}.
  • Parser — модуль, отвечающий за загрузку HTML и извлечение необходимых данных (заголовок, описание).
  • Worker (Celery) — рабочие процессы, выполняющие асинхронные задания.
  • Redis — брокер сообщений и хранилище статусов задач.
  • PostgreSQL — база данных для сохранения результатов парсинга.

Использование API

Синхронный режим

POST /parse/http

Пример запроса:

{
  "urls": [
    "https://codenrock.com/global-rating/sport_programming"
  ]
}

Асинхронный режим

POST /parse/async

Пример запроса:

{
  "urls": [
    "https://codenrock.com/global-rating/sport_programming"
  ]
}

Проверка состояния GET /tasks/{task_id}


curl http://localhost:8010/tasks/{task_id}
