Сравнение и выводы

Задание 1. Сумма чисел от 1 до 10^13

Метод Время (с) Пояснение
Asyncio 4.82 Асинхронность не помогает для CPU-bound задач, GIL мешает.
Threading 4.73 Потоки конкурируют за GIL, прироста нет.
Multiprocessing 2.25 Реальное ускорение за счёт параллельного выполнения на нескольких ядрах.

Выводы:
- Threading и Asyncio бесполезны для тяжёлых вычислений из-за GIL.
- Multiprocessing — лучший вариант для задач, нагружающих CPU.
- Для IO-bound задач подойдут Asyncio или Threading.
- Деление задачи на сегменты (chunking) — простой и эффективный способ распараллеливания.

Задание 2. Параллельный парсинг веб-страниц

Метод Время (с) Пояснение
Asyncio + aiohttp 1.185 Очень быстрый: все запросы обрабатываются параллельно в одном потоке.
Threading 2.036 Потоки тоже ждут сеть, но их управление чуть тяжелее.
Multiprocessing 2.605 Создание процессов накладно, для IO-bound задач почти не даёт выигрыша.

Выводы:
- Для сетевых задач и работы с БД (IO-bound) лучше всего подходит Asyncio: минимальная задержка, высокая эффективность.
- Threading немного хуже, но проще в реализации.
- Multiprocessing не даёт преимуществ и только замедляет из-за накладных расходов.
- Для CPU-bound задач (математика, расчёты) лучше Multiprocessing, для IO-bound (сеть, файлы, БД) — Asyncio.
- Важно правильно делить задачи на чанки (URL-списки, диапазоны чисел) для равномерной загрузки.
